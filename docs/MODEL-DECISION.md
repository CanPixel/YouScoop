# Model decision and corrections to the pasted Gemini chats

The pasted chats are background for this decision, not instructions or verified evidence. Their central useful point is that a model file does not fetch or decode a YouTube URL by itself. The application must acquire the media, retain timestamps, and decode inputs. A transcript remains a valuable full-length index, but it does not contain on-screen documents, speaker changes, tone, or visual context.

The chats conflate Qwen2.5-VL with an audiovisual model. Qwen2.5-VL handles text, images, and video frames. The current [SmolVLM2 model card](https://huggingface.co/HuggingFaceTB/SmolVLM2-2.2B-Instruct) lists video, images, and text inputs, not audio; YouScoop uses it for visual descriptions. [Qwen2.5-Omni](https://qwenlm.github.io/blog/qwen2.5-omni/) is the relevant model for synchronized audio and video input: its Thinker has audio and image encoders, and its time alignment relates audio to video frames. This justifies using Omni for selected ten-second investigations while keeping timestamped captions and frame descriptions for navigation. It does **not** justify claiming that twelve sampled clips reveal the whole two-hour video. Original recordings and exact model outputs remain inspectable.

The chats' fixed 768-frame cap, 1,200 images becoming a particular number of vision tokens, and universal 40-minute or 45-minute transcript token counts are configuration and content dependent, not model laws. A large text window also consumes memory for the weights, attention cache, and prompt processing. The recommendation that a 32B model Q4 fits *comfortably* on 16 GB, or that 70B is practical on this 24 GB Mac, is unsound for this workflow. The actual Mac trial is the more relevant evidence: Gemma 4 26B A4B Q4 used 14.29 GB MLX peak on a short question, and its first completed response took 25.96 seconds. Whole-source summaries misplaced some timestamps. An optional bounded chat, with citations mapped to supplied evidence IDs, is a better role for it.

[Google's model card](https://huggingface.co/google/gemma-4-26B-A4B/blob/main/README.md) lists 25.2B total parameters and 3.8B active for 26B A4B. The active count reduces computation per token, but the other experts still occupy memory. This variant accepts text and images, **not audio**; it cannot replace Omni for synchronized sound and video. Google lists a 60-second video-frame input limit at one frame per second, also far below a two-hour source. Its role here is desktop investigative text chat. We tested a local MLX conversion on this Mac, not full native multimodal Gemma ingestion.

MLX is a useful Apple Silicon runtime for Gemma. The working local Omni path uses Transformers and PyTorch MPS because the installed MLX packages did not offer a verified equivalent audiovisual path. ONNX is a deployment format and runtime family, not an automatic model conversion or proof of equivalent decoding. The archive already runs small GGUF text and embedding models through llama.cpp on Mac and Android. Changing that functional mobile path to ONNX would require a separately measured benefit and compatible model conversion.

The archive has a different memory budget and purpose. Its Qwen3 4B Q4 text model and BGE-small embedding model are installed separately, with local Whisper small for voice input and system speech output. Voice is half duplex. Neither an open model, offline use, nor an evocative interface guarantees truthful answers or absence of refusals. Every claim needs a traceable source, original wording, interpretation status, and room for human correction. In the test video the speaker says **Baal**. The source caption and Whisper sample rendered **Ball**; the archive stores that as an explicit corrected reading while preserving the original. This spelling correction does not verify the speaker's bank-account allegation.

The earlier 32:45 source trial yielded 124 evidence passages, including twelve Omni audio and video inspections. Their generation consumed about 161 seconds in total, excluding setup, decoding, captioning, and indexing. Cancellation after the first clip preserved its result, and resume completed the next. Several raw Omni outputs repeated phrases, switched language, or invented financial details. We traced most of the repetition to the model continuing with invented dialogue after its first answer. A first-paragraph generation stop removed that continuation on a problem clip, but it cannot guarantee the first answer is correct. The current package therefore preserves raw Omni outputs as artifacts while excluding them from searchable evidence; only a human-written, reviewed observation is promoted. The current unreviewed test source exports 112 evidence passages and 69 artifacts. The earlier Android ARM64 storage probe imported, reimported, exported, and restored the older 124-passage package. Full two-hour processing speed, complete visual coverage, physical Fold latency, microphone interaction, and Android import of the revised package remain unmeasured.
